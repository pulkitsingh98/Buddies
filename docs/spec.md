# Build "DeskPals": photo-to-desktop-pet platform (macOS + Windows)

> Working name is DeskPals. Rename freely.

You are building a cross-platform desktop app (macOS and Windows) together with a Supabase backend. A user uploads a photo of a person, animal or object. The app turns it into a small animated pet that lives on their desktop, lifts their mood, runs gentle wellbeing reminders and timers, does a few safe desktop chores, and can visit, nudge and message friends' pets in real time.

It starts with two users (me on a Mac, my girlfriend on a Windows laptop). It must be built as a platform from day one so friends can sign up, make their own pets and connect.

Work in phases (listed below). Before writing code, read this whole document. Then propose a short plan for Phase 0 and Phase 1 and list any decisions you need from me. After that, build. Commit after each meaningful step with clear messages, and keep a `CLAUDE.md` in the repo up to date with architecture notes, commands and conventions.

---

## 1. Non-negotiable principles

1. **Light on the laptop.** The pet runs all day, so it must feel invisible on CPU, RAM and battery.
   - Idle target: under 1–2% CPU and under ~150 MB RAM.
   - Animate at no more than 30 fps, and drop to a few fps (or freeze) when the pet is idle or asleep.
   - Pause rendering entirely when a full-screen app or game is in front, or when the screen is locked.
   - No busy polling of the server. Use Supabase Realtime websockets, with exponential-backoff reconnects.
2. **Never destroy user files.** Desktop chores only _move_ files and never delete them. Every action is logged locally and can be undone with one click. Show a preview (dry run) before the first tidy.
3. **Consent and privacy.**
   - Pets made from a photo of a real person require a checkbox: "I have this person's permission."
   - Pets and messages are visible only to accepted friends. Users connect by sharing a friend code; there is no public discovery.
   - Deleting a pet deletes its images from storage.
   - Original photos are processed into the pet and then discarded. Don't keep originals on the server unless the user opts in.
4. **Secrets never ship in the app.** The desktop app uses only the Supabase URL and anon key. Any third-party AI or API keys live in Supabase Edge Function secrets.
5. **Cross-platform parity.** Every feature works on macOS and Windows. Handle platform quirks explicitly, as listed in section 9.

## 2. Tech stack (use these unless you find a concrete blocker; if so, tell me before switching)

- **Desktop shell:** Tauri v2 (Rust backend plus a web frontend). It's much lighter than Electron. Check the current stable versions of Tauri and its plugins before starting.
- **Frontend:** React + TypeScript + Vite. Use plain Canvas 2D or CSS transforms for the pet animation. Only add PixiJS if Canvas becomes a real limitation.
- **State:** Zustand (or similar small store).
- **Local persistence:** SQLite via the Tauri SQL plugin, for settings, reminders, the file-action undo log and a message cache.
- **Backend:** Supabase.
  - Auth: email magic link, plus Google sign-in if easy.
  - Postgres with Row Level Security on every table.
  - Storage for pet sprites.
  - Realtime (Broadcast and Presence) for live interactions.
  - Edge Functions for anything that needs secrets.
- **Tauri plugins as needed:** autostart (launch at login), notification, global-shortcut, updater, single-instance, store/sql, and fs with scoped permissions.
- **Monorepo layout:**
  ```
  apps/desktop/          # Tauri app (src-tauri/ + src/)
  supabase/              # migrations/, functions/, seed.sql, config
  packages/shared/       # shared TS types (DB types generated by Supabase CLI), constants
  docs/                  # architecture notes, decisions
  .github/workflows/     # CI + release builds
  ```
- **Builds and releases:** GitHub Actions with `tauri-action`, producing a macOS `.dmg` (Apple Silicon and Intel, or universal) and a Windows installer (`.msi` or NSIS `.exe`) on tag push. Publish to GitHub Releases. Wire the Tauri updater to those releases so friends get updates automatically.

## 3. Windows and pet behaviour

- Each visible pet runs in its own **transparent, borderless, always-on-top window** with no taskbar or dock icon. The window is sized to the pet (plus room for a speech bubble), not full-screen, to keep compositing cheap.
- **Click-through except on the pet.** Use Tauri's `set_ignore_cursor_events`. Toggle it based on whether the cursor is over a non-transparent pixel of the pet, checked cheaply (a low-frequency cursor position check from Rust, or the sprite's alpha mask). Clicks on empty space must reach the apps underneath.
- **Tray / menu bar icon** with these items:
  - Show or hide pets
  - Start a focus timer
  - Tidy Desktop
  - Friends
  - Settings
  - Pause for 1 hour
  - Quit
- **Behaviours (a simple state machine):**
  - idle: breathe and blink
  - walk along the bottom of the screen
  - sit
  - sleep, after the user has been idle N minutes (use a cross-platform idle-time API)
  - wake up when the user returns
  - get dragged and dropped, wobbling while held
  - get petted (click or hover → hearts and a happy reaction)
  - celebrate
  - be sleepy late at night (gentle "go to bed" nudge after a configurable hour)
- Pets stay within screen bounds and handle multiple monitors and display scaling (HiDPI on Mac, 125%/150% on Windows).
- The user can choose which of their pets are "out" (one or several at once).

## 4. Pet creation pipeline (photo → pet)

Design this behind an interface, `PetGenerator`, so styles can be added later without touching the rest of the app.

**Phase 1: Cutout style (ship this first)**

1. The user picks an image (drag-drop or file picker) and types a name for the pet.
2. Remove the background. Prefer on-device inference (for example, an ONNX segmentation model run via onnxruntime) so it costs nothing and photos stay local. **Check the model's and library's license before using it**; it must allow commercial-style redistribution, and I'd rather avoid AGPL. If on-device isn't practical, use a Supabase Edge Function that calls a hosted background-removal API, with the key stored as a function secret.
3. Show a crop and adjust screen: the user positions and scales the subject and can nudge the mask edges.
4. Auto-stylize slightly: a soft white outline, a subtle drop shadow and a "chibi" squash. Head emphasis is optional.
5. Animate procedurally from the single cutout. Each of these states is a parameter preset, not separate art:
   - bounce and breathe
   - squash and stretch
   - tilt
   - blink (an eyelid overlay if eyes can be located; otherwise skip)
   - wobble when dragged
   - flip direction when walking
   - lie down and fade when sleeping
6. Upload the processed sprite (PNG/WebP) plus a small JSON manifest to Supabase Storage, so friends' apps can render the pet when it visits them.

**Phase 4: Stylized style (later)**

- A cartoon or pixel-art redraw via an image-generation model in an Edge Function.
- Generates a fixed pose set (idle, walk ×2, sit, sleep, wave, happy, sad) with character consistency.
- Stored as a sprite sheet plus manifest, using the same rendering contract as the cutout style.

Pets can be made from people, animals or objects; the pipeline must not assume a face.

## 5. Wellbeing: reminders, timers, mood

All of these are delivered by the pet itself: a speech bubble plus an animation, and an optional system notification. Every one is configurable in Settings, and all respect **quiet hours** and **"don't interrupt when full-screen / screen sharing / in a meeting"** (best-effort detection of full-screen apps).

- **Water reminder:** default every 60 min. Snooze or "done" buttons, plus a daily glass counter.
- **Stretch reminder:** default every 45 min. Each one includes a short, varied stretch tip from a local list.
- **Eye break:** 20-20-20 rule, default off.
- **Focus timer (Pomodoro):** 25/5 default, customizable. The pet sits "working" beside you during focus, then celebrates at the end of the session and suggests a break. Track a daily streak locally.
- **Mood boosts:**
  - a daily good message (a local curated list of 200+ kind, non-cringe messages; no AI needed for v1)
  - random small compliments at low frequency
  - a celebration when a timer completes
- **Mood check-in (optional, once a day):** the user taps an emoji. Friends can see your current mood status only if you choose to share it.
- Store everything locally. Sync only what's social (mood status, messages).

## 6. Desktop chores (safe file actions)

Implement these as Rust commands with **scoped file-system access** limited to the folders the user explicitly enables.

1. **Tidy Desktop:**
   - Group loose files by type into `Desktop/Tidied by <PetName>/<YYYY-MM-DD>/{Images, Documents, Screenshots, Videos, Archives, Code, Other}`.
   - Show a preview first.
   - Skip folders, aliases/shortcuts, hidden files and files currently open or locked.
   - Never overwrite a file; add `(1)`, `(2)` suffixes instead.
2. **Sort Downloads:** the same rules, applied to the Downloads folder (opt-in).
3. **Quick create:**
   - a new folder with a name the user types
   - a new quick note (a `.txt` or `.md` file on the Desktop or in a chosen folder)
4. **Undo:**
   - Every operation is written to a local SQLite log (source path, destination path, timestamp, batch id).
   - "Undo last tidy" restores the whole batch.
   - Keep 30 days of history.
5. Before each operation, check that the needed permission has been granted.

## 7. Social layer (pets interacting across machines)

- **Accounts and profiles:**
  - Sign up, display name and avatar (the avatar can be one of your pets).
  - Each user has a short, unique, shareable **friend code**.
- **Friends:**
  - Add by code → request → accept or decline.
  - Remove and block.
  - A friends list with online presence and optional mood status.
- **Interactions, all delivered in real time:**
  - **Visit:** your pet walks in from the edge of your friend's screen, shows a speech bubble with your message, does an animation, waves and walks off. If the friend is offline, it's queued and delivered when they next come online.
  - **Nudge:** a quick "poke". The friend's own pet reacts (jumps, or looks toward the screen edge) and shows "<Name> nudged you".
  - **Heart / "thinking of you":** floating hearts from your pet.
  - **Quick message:** text, max ~200 characters, shown in a bubble. The friend can reply from the bubble without opening a chat window. Keep recent history in a small messages panel.
  - **Hang out:** when both users are online and both opt in, the friend's pet can stay on your screen for a while and the two pets play together (simple paired animations).
- **Safety:**
  - Rate-limit nudges and messages per sender in the database (for example, via a Postgres function or RLS check plus a counter).
  - Only accepted friends can send anything.
  - A blocked user is silently dropped.
  - A global "Do not disturb" setting queues incoming visits.
- **Realtime design:**
  - Use Supabase Realtime **Presence** for online status.
  - Use **Postgres-backed inserts** for messages and nudges so they persist and can be delivered after the friend was offline.
  - Use **Broadcast** for ephemeral things like hang-out animation syncing.
  - Each client subscribes only to its own channel (`user:<id>`), plus a presence channel scoped to friends.

## 8. Data model (Supabase; write as migrations under `supabase/migrations`)

Suggested tables (refine as needed). **RLS on every table.**

- `profiles` (`id` = auth.uid, `display_name`, `friend_code` unique, `avatar_pet_id`, `mood_emoji`, `mood_shared` bool, `created_at`)
- `pets` (`id`, `owner_id`, `name`, `kind` [person | animal | object], `style` [cutout | stylized], `sprite_path`, `manifest` jsonb, `consent_confirmed` bool, `created_at`)
- `friendships` (`id`, `requester_id`, `addressee_id`, `status` [pending | accepted | blocked], `created_at`). Add a unique constraint so a pair of users has only one row.
- `interactions` (`id`, `sender_id`, `recipient_id`, `pet_id`, `type` [visit | nudge | heart | message | hangout_invite], `body` text null, `delivered_at`, `seen_at`, `created_at`)
- **Storage bucket** `pets`. Its policies: the owner can write, and the owner plus accepted friends can read. Use signed URLs if simpler.
- **Helper SQL functions:**
  - `are_friends(a, b)`
  - `send_interaction(...)`, which checks friendship, block status and the rate limit
  - `accept_friend(code)`

Generate TypeScript types from the schema into `packages/shared`.

Local SQLite holds: settings, reminder schedules and counters, focus-timer history, the file-action undo log and a cache of recent interactions.

## 9. Platform specifics to handle

**macOS**

- Transparent windows need the `macOSPrivateApi` setting in Tauri.
- Hide the dock icon (accessory activation policy).
- Make sure the windows work across Spaces and full-screen apps, or deliberately hide during full-screen.
- The first access to Desktop or Downloads triggers macOS privacy prompts. Explain this in onboarding.
- Unsigned builds trigger Gatekeeper. Document the "right-click → Open" workaround in the README, and leave a CI hook for notarization once I have an Apple Developer account.

**Windows**

- Relies on WebView2 (bundle the bootstrapper).
- Hide from the taskbar.
- Get the Desktop path via the Known Folders API, because the Desktop is often redirected into OneDrive.
- Unsigned installers trigger SmartScreen. Document this, and leave a code-signing hook in CI.

**Both**

- Launch at login (opt-in).
- Single instance only.
- Correct per-monitor DPI handling.
